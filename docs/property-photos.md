# Property photographs

The editor accepts up to 40 JPEG/JPG, PNG or WebP files, each at most 10 MB. `MAX_PROPERTY_PHOTOS` is shared by the editor, validation, story analysis and video source validation. Existing installations must run the entire `supabase/sql-editor-forty-photos.sql`; success is `MBP_40_PHOTOS_READY`. The migration changes only the photo-count check, preserves existing data and can be reapplied.

Photos are processed sequentially in the browser to bound memory use. Each is resized to a maximum 2,000-pixel side without enlarging small originals, preserving aspect ratio, and encoded as WebP at quality 0.86. Browsers that cannot produce WebP fail instead of saving incorrectly labelled data. Avatar processing remains at 512 pixels.

Property uploads use authenticated XMLHttpRequest to the same Supabase Storage bucket with the signed-in session JWT and existing ownership policies. Progress is the completed-photo count plus the current file's transfer fraction, divided by the batch count. It is capped below completion until Storage acknowledges the upload; conversion starts at the previous completed percentage. No timer invents transfer progress. Uploads time out after three minutes, report errors, release the UI and retain any successful photographs in the editor. The agent still saves the listing to persist its photo references. Files have unique names, no upsert, and a one-year public cache lifetime.

`PropertyImage` generates responsive Next.js Image Optimization srcsets for the configured public property-images bucket and bundled sample photographs, while retaining original src URLs as fallbacks. The allowlist is restricted to that bucket on the configured Supabase host. The optimizer serves cached WebP at widths up to 2,000px and quality 80; smaller images are not enlarged. Other external images and browser demo data URLs keep their original source. Gallery images load lazily and decode asynchronously. Cover images load eagerly with high priority; the photo dialog loads its current image eagerly. The Editorial pinned section mounts only the active and neighboring images instead of loading every stacked image at once; mobile and reduced-motion layouts retain normal lazy scrolling.

The film still selects at most 23 unique scenes from the available photos, preserving the 3.4-second scene timing and 78.2-second maximum. Increasing the gallery capacity does not increase that duration cap or initiate a paid generation.

Validation covers all accepted formats converted to WebP, authentic upload headers and owner paths, visible progress, failed transfers retaining successful photos, 40-image galleries, responsive srcsets, nearby-only pinned images, the database 40/41 boundary and existing template interactions. A local Image Optimization request returned a cached 320px WebP of 15,012 bytes from the 97,837-byte sample JPEG; real sizes and loading times depend on each photo, device, connection and cache state.
